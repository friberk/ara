# AI Research Assistant

Single-user CS 59300 homework application. `hw1.md` is the assignment authority; `docs/implementation-plan.md` is the approved project plan. Required workflows: academic search, persistent library, PDF upload/metadata, content-grounded summaries, paper-grounded Q&A. Homework due October 10, 11:59 PM; app 60%, reflection 40%.

## Architecture

- **Open (local) models are experimental and frozen (2026-10-09, ARA-090).** Everything open-model sits behind `EXPERIMENTAL_OPEN_MODELS` (default off) and the `open-models` Compose profile. Don't develop them further, or plan features around them, unless the user lifts the freeze. Keep their tests passing with the flag on. The open-model rules below apply only when the flag is on.
- `src/backend`: Python 3.13, FastAPI/Pydantic v2, async SQLAlchemy/psycopg 3, Alembic, httpx, Dramatiq/Redis, PyMuPDF. Separate routes/schemas/models/repositories/services/integrations/jobs.
- `src/frontend`: React/Vite, strict TypeScript, Tailwind v4/shadcn, React Router, TanStack Query; React Hook Form/Zod for forms. No initial Zustand.
- Compose runs frontend, api, worker, PostgreSQL, Redis and MinIO plus migration/bucket-init gates; model-worker and Ollama run only under the `open-models` profile. Default local inference uses CPU; NVIDIA/AMD overrides are optional and require compatible Linux hosts.
- PostgreSQL 17 includes pgvector; `0007_feature_merge` joins full-text and retrieval migrations without rewriting their existing revisions. Old chunk sets rebuild through startup jobs while stored citation snapshots remain readable. RAG uses structured PyMuPDF extraction, profile-specific indexes, retrieval provenance and model-specific context/memory budgets. ARA-080/081 remain open resource/quality limitations.
- PDFs belong in MinIO; metadata, pages/chunks, jobs, summaries and chats belong in PostgreSQL. Complete and partial model weights belong in the `ollama-models` named volume. Startup never downloads weights; existing stale installations prepare through background checks. Core readiness is independent of Ollama.
- Every request/actor/parallel task owns its AsyncSession. Engines/clients belong to one process/event loop. PyMuPDF runs in child processes, never concurrent threads or the API event loop.
- PostgreSQL job/outbox state is authoritative; duplicate deliveries must be safe. Chat request UUIDs must not replay paid generation. Page citations must belong to the selected document.
- Local model mutations and global inference admission use durable PostgreSQL ownership. Pause is complete only after the managed runtime acknowledges settled work; recovery must settle every unresolved current or previous operation UUID before releasing ownership. Unknown valid UUID pause establishes a per-daemon canceled tombstone, so late same-UUID pull is rejected. Never infer safe settlement from 404 or restart the daemon to pause.
- Unconfirmed transfer failures remain fenced in durable `settling` cleanup until acknowledgment; do not admit inference or another mutation while pending UUIDs exist. Summary provenance is checkpointed under admission, not reread after generation. Native sampling explicitly uses temperature 0.0.
- Local selection requires verified artifact/runtime/context capabilities. Preserve defaults and histories when deleting weights; never fall back from a local request to paid generation. IFM 7B has live ARM64 CPU paper-workflow evidence; the user's 3.7B passed automatic readiness in ARA-053. Fixtures do not prove paper quality, 27B or GPU feasibility. The 12g ceiling is not startup resident memory and does not accommodate 27B by itself.
- Reasoning controls belong to each model. Hosted entries are keyed by model ID; native entries use verified `thinking.values`/`thinking.default` and exact Boolean/string mappings. Never infer named levels from HTTP 200 or obsolete `thinking_levels`. Capability-schema/runtime changes require verification using retained weights.
- Reasoning menus expose explicit model levels; IFM uses None/Low/Medium/High and binary-only models use a Reasoning toggle. Resolve legacy preferences only through verified per-model `reasoning_aliases`, with direct supported targets. Preserve unavailable preferences, raw API compatibility and immutable history; never automatically save a display normalization.
- Refresh previously ready, desired-ready local models automatically through durable verification-only jobs. Preserve user pause/delete/failure intent and inference admission. Verify-only retry/recovery must never pull missing weights. Keep runtime inspection off the core dispatch loop; derive installation operation and historical job operation labels without migrations. Routine upgrades require no manual Verify action.
- Validate Ollama inventory/metadata/probe shapes at the integration boundary. Malformed fields raise a safe permanent protocol error and settle model jobs; never let attribute/type errors create endless expired-lease recovery. Cancellation and database outages retain their own semantics.
- Canonicalize the observed `【source:UUID】` wrapper before final citation validation, persistence and active-checkpoint reuse. IDs and document membership remain strict; malformed/foreign sources fail. Do not promote failed generations or replay requests while correcting formatting.

## Commands

Bootstrap: `python3 scripts/bootstrap.py`. Start: `docker compose up --build`. Logs: `docker compose logs --tail 100 api worker` (add `model-worker ollama` with open models on). Migrate: `docker compose run --rm migrate`. Backend tests: `python3 scripts/test-stack.py test` against isolated real services; never run destructive integration fixtures on development data. Frontend: `docker compose exec frontend npm run check` and `npm run build`. Browser fixtures, GPU overrides and the opt-in isolated 7B runner are in README. Stop: `docker compose down` without `--volumes` to preserve data and weights. Demo deploy: CI's `deploy` job after `verify` on `main`, or `SITE_HOST=vps-eb56b28c.vps.ovh.us scripts/deploy.sh ara-deploy@15.204.210.41`; server logs: `ssh ara-deploy@15.204.210.41 'cd /opt/ara && docker compose logs --tail 100 api worker caddy'`. Caddy lets Purdue's AS17 addresses in without a password and asks everyone else for the demo login; Purdue's VPN is split-tunnel, so it does not count as campus (README).
